# 启动响应性修复设计

基线：main `7d4da62735782c379e1face26abf6ac7294499df`。本轮复用已合并且干净的工作树，保留原分支记录。

目标是启动期间窗口可响应，并减少与首屏无关的完整历史读取。现有历史分页、消息格式、原线程绑定、权限、委派和旧运行分支保持一致；不改输入法或网络代理。

## 数据流与职责

1. 自动化目标列表只需会话元信息。由现有 SingleChatMessageStore 提供元信息读取，历史层沿用 manifest、索引校验、忙碌状态和删除边界；AutomationTargetPolicy 不读取消息正文或工具时间线。
2. 仍然需要正文的历史投影在独立 Worker 中执行同步 SQLite JSON 投影及 JSON 解码。主进程先在现有串行队列中校验索引，再等待 Worker 的只读结果；保持同一代际、相同顺序、相同字段及错误语义。Worker 不重建或修改索引，不读取凭据，也不发送网络请求。
3. PrototypeProvider 当前在历史就绪前不渲染子页面。将空白等待替换成沿用现有主题的轻量启动状态，保留原生标题栏操作与拖动区域；实际读取完成后立即进入原页面，失败时明确提示并允许重试，不使用固定延时或虚构进度。

文件归属：历史和 Worker 属于 conversation；目标列表属于 automation；启动状态组件属于 renderer/ui；加载和重试生命周期沿用 useSingleChatHistory 与 PrototypeProvider。Worker 必须单独存在以运行于独立执行上下文，不新增通用 SQL 执行接口或 IPC 频道。

## 已确认的启动动画

用户确认圆润五角星版本：星形角色从信封中醒来，四个小伙伴带着气泡汇合，最后只保留中央角色及轻量漂浮／眨眼。无产品名称、模拟标题栏、窗口按钮或聊天展开；提示文字位于信封下方，留出安全间距。

动画由 `StartupStatus.tsx` 与同领域样式 `styles/startup.css` 实现。装饰不参与加载状态：开场 8.8 秒只播一次，超时后仅轻量等待动作循环；PrototypeProvider 的资料就绪条件满足即直接卸载动画并渲染原页面，无最短展示时长、动画完成回调、退出过渡或新增计时器。几乎立即完成、开场中途完成及等待循环中完成均适用。

采用声明式 CSS 的 transform／opacity 动画，不移入预览中的逐帧 JavaScript、播放控件或演示进度。失败后停止动画并显示原有失败提示和重试；减少动画设置显示静态星形角色。系统原生窗口操作及拖动区域保留。

## 验证计划

- 元信息路径回归：相同会话资格、线程、工作区和忙碌状态，禁止调用完整历史投影，兼容旧存储。
- Worker 回归：富消息投影与原行为一致、筛选和顺序正确、代际及损坏错误不隐藏、读取后及时关闭；合成大消息证明重计算期间主线程仍有心跳。
- 启动 UI 回归：延迟成功、失败重试、真实状态切换、原页面和草稿行为；浅／深色、窄窗口及减少动画设置。
- 定向和默认全量、类型、Lint、能力词典、隐私、Renderer/Main 构建，以及隔离的 Windows/Electron 组合验收。

边界：大日志本身不等于每次启动全量重读；本轮只读诊断时索引有效。异常索引重建和首次迁移仍使用原有串行恢复路径，本轮不更换数据格式或自动清理历史；不能把投影的局部测量当作完整启动耗时。

## 当前验证结果

- 修复前回归先失败：元信息读取触发主线程富消息 SQL；历史未就绪时页面为空，没有启动状态。失败记录保留，不覆盖。
- 定向 64 项通过；默认全量 296 个文件、2137 项通过、原有 2 项 TODO。类型通过；Lint 为原有 15 条 Hook 警告，无错误。
- 隔离 Windows Electron 验证首次迁移、强退后恢复同代际和消息、工具输出分页及无效引用拒绝，通过。未启动或重启日常资料实例。
- 合成 256 MiB 富消息投影两次对比：旧主线程路径约 300–359 ms、最大心跳间隔约 316–376 ms；Worker 路径约 326–381 ms、最大心跳间隔约 16 ms。元信息读取约 1.4–1.6 ms。此结果说明主线程阻塞降低，不宣称查询总耗时加速或等同实际冷启动。
- 另将历史服务与嵌入式 Worker 实际构建后，在 Windows Electron 44.2.0／Node 24.20.0 的独立 Main 中读取合成富消息，确认同序返回、时间线剥离且 Main 定时器继续执行。Main、Preload 和 Renderer 均实际构建；没有安装器、发行物或标签。
- 浅色及深色窄窗口通过加载、失败、手动重试、原聊天页切换，无横向溢出或浏览器异常；减少动画设置停止旋转，等待历史时画面继续刷新。截图只含合成数据。

新增产品文件为只读 Worker 源、启动状态组件及其同领域动画样式：Worker 必须进入独立线程，组件承接加载／失败界面，独立样式维护星形、开场与等待动效，避免继续堆入全局样式。角色的共用局部绘制函数保留在组件内；索引、投影服务、目标资格和加载生命周期均沿用现有模块，没有纯转发文件或新 IPC。

动画接入定向回归 12 项通过，包含加载 0／4000／20000 ms 后直接进入主页面，未发送动画结束事件或额外推进时钟。真实浏览器覆盖浅色、深色、窄窗口和 320×480 减少动画，确认圆弧轮廓、信封与文字间距、单次开场／无限等待配置、失败停止及可见重试按钮。受控加载就绪至原输入框显示约 84–121 ms，属于合成资料和本机测试结果，并非日常资料启动耗时。

动画接入后默认全量 296 个文件、2140 项通过，原有 2 项 TODO；首轮并行验收时既有 AgentChatFlows 一项超时，保留失败记录，单独 4 项及随后不并跑重任务的默认全量均通过，未改测试超时或产品聊天逻辑。Windows Electron 首轮强退恢复检查完成后，自动清除临时目录遇到 EPERM；原记录保留，以保留证据模式复查通过，不修改公共测试工具或日常资料。类型、Lint、能力词典、隐私及 Renderer 构建通过；Lint 保留原有 15 条警告。
