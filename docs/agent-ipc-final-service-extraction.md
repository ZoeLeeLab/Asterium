# agentIpc 业务辅助逻辑收尾

基线：main `eab6b7d7aee207eae28bcae28f6f0514f5d9f331`。复用现有委派权限工作树，在独立分支实施；旧已合并分支记录保留。

目标是让 `agentIpc.ts` 负责依赖构造、注入、领域 IPC 注册、启动和统一清理。按业务边界迁移具体执行策略，不建立通用 Agent Service，不增加注册框架。

## 四组归属与数据流

1. **运行时解析**：本地运行时解析模块拥有 Codex／Claude 安装缓存，统一选择、刷新、导入线程核对、目录和工作区授权解析。IPC 与运行启动继续共用这一所有者，保留现有刷新时机、错误及保护目录检查。
2. **消息启动与事件协调**：API／本地运行启动模块负责消息准备、工作区、幂等指纹和适配器配置；运行事件模块负责绑定、交付、领域后处理及失败传播。既有 RunCoordinator、Factory、Port 继续各司其职。旧运行路径单独保留，仍由 `ASTERIUM_USE_LEGACY_RUN_PATH=1` 选择。
3. **工具及委派**：委派执行与工具处理器承接目标筛选、附件快照、read/write 提示和发送前复查；运行工具按实际会话绑定记忆、笔记、自动化及群聊能力。既有持久队列、回传和历史隐藏服务不重写。
4. **其他领域回调**：会话压缩／资料重载、日记生成、工作室轮次、自动化资格与执行等回调各回到对应领域模块；校验器和导出辅助函数归入对应契约或领域工具。主文件保留薄的注入与事件连接。

数据流保持 Renderer → 原有领域 IPC → 业务服务 → 原有运行协调器／适配器 → 事件及存储。主文件只装配这些对象。运行时引用继续延迟读取，避免注册时固定尚未就绪的引用。

## 必须保持的行为

- 全部 230 个 invoke 频道各注册一次，注册顺序、校验顺序和返回值不变；统一退出清理仍由组合根发起。
- 写租约、取消、失败与释放顺序不变。复用的本地适配器只在本轮租约内重绑工具和工作区；排队用户消息不提前改变正在运行的汇报配置。
- 委派保留严格 v1 接口及 read/write 提示、原线程回传、跨轮读取、用户消息优先、重启不盲目重发、内部消息隐藏。
- `ASTERIUM_USE_LEGACY_RUN_PATH` 的已有启动、事件、取消及清理行为全部保留，不删除旧路径，也不把默认路径新增行为顺手移植到旧路径。
- 不修改页面布局、资料格式、存储路径、Preload、默认测试配置或 CI。

每组迁移前后运行对应现状及回归测试，独立提交。最终运行默认全量、类型、Lint、能力与隐私检查，以及 Windows 累计合成验收。验收只使用独立数据目录和本地合成模型，不连接日常配置、私人凭据或真实服务器。

本轮不推送、合入 main、打包或清理其他工作树。代码提交存在并经过核验后，再以纯文档提交更新能力绑定及最终验证记录。
