# 群聊附件

图片缩略图从已授权的本地快照字节生成，不依赖 Windows 缩略图缓存或文件扩展名。图片无法解码出缩略图时显示普通图片图标；只要快照本身有效，仍可点击预览和按原规则发送。快照实际缺失或访问校验失败仍阻止读取。PNG/JPEG 的缩略图与 WebP/GIF 的解码或图标降级分别核验，不把缩略图失败写成文件丢失。此修改纳入本地 r4 候选准备，旧 r3 安装包不包含该修复。

在工作室群聊输入区，可以点击“附件”选择图片或文件，也可以直接拖入，或用 `Ctrl+V` 粘贴资源管理器复制的文件和剪贴板里的截图。拖放、粘贴只添加草稿，普通文字粘贴仍照常。每条消息最多 10 个附件，单个不超过 20 MiB；可附带文字与 @伙伴，也可只发送附件。发送前可移除选择，选择对话框失败或超限会显示错误。

附件会共享给本群伙伴。发送时保存独立历史快照，原文件之后修改、移动或删除不改变已经发送的内容。群聊记录中的卡片可点击预览，重新打开群聊仍可查看快照。应用运行期间，文字和待发送附件按群聊暂存，切走后返回原群仍可继续编辑。完全退出应用会清理待发送附件。群聊进行一轮讨论时可继续输入文字，附件选择与发送需等待本轮结束。

## 伙伴如何使用

- 本地 Claude Code 与 Codex：复用既有附件解析器接收只读快照路径，按任务需要和原审批方式读取。模型能否识别具体格式取决于官方 CLI、模型及工具能力，不保证任意文件格式均可理解。
- API 伙伴：复用单聊的附件机制。支持并配置原生多模态的模型可接收符合能力声明的图片；文本附件通过现有 `read_attachment_text` 工具读取。PDF、Office 或其他二进制格式不会因此自动转换成模型可读文本。
- 外部现有线程伙伴：群聊 MCP 历史仅提供附件名称、类型、大小及 ID，不传输文件内容或本机路径。文件内容需另行共享；界面在选择附件后明确提示这个限制。

每条消息的名称和 ID 会进入群聊公开上下文；内部托管伙伴的本轮原生/多模态输入最多附带上下文中最近 10 个唯一附件，其他已发布附件仍保留在该群的会话文件范围内，可按 ID 查询，不把上下文预算解释为自动解析全部历史文件。

## 数据边界

群聊发送时，主进程只接受由桌面附件服务产生的待选 ID，不接受渲染页自造快照路径或附件元数据。群聊附件使用独立存储命名空间；主进程在准备当前群聊原生绑定及消息序号后，为该运行绑定公开附件 ID。单聊、其他群聊、未发布的新消息和未注册绑定不能经附件解析器读取这些快照。退出重开后由主进程从保存的群聊账本重新建立读取关联，不依赖前端凭据。

这复用现有业务校验，不改变 Full 模式含义：用户授权的原生命令仍可以使用当前 Windows 账户权限。导出群聊 Markdown 只导出附件元数据，不内嵌文件本身；删除原文件与星丛历史快照是不同操作。

## 项目文件

用户在项目群聊发送成功后，星丛会把附件快照复制到该项目的 `uploads/`，首次使用时创建文件夹。同名但内容不同的文件按序加后缀，不覆盖已有文件。归档失败时消息仍保留，点击「重试归档」只补存文件。单聊不会自动归档，仍可手动选择「保存到项目」。

工作室的「项目文件交付」浏览项目根目录及子目录。它同时展示手动放入的文件、群聊上传资料和已在项目内的 AI 成品。交付工具的登记规则保持原样；新建项目不再预建 `deliverables/`，已有目录和内容保留。

自动检查使用合成文件与隔离目录；实际伙伴查看图片、读取文档及多人协作仍须在新候选界面验收，不能只凭卡片出现便视为已理解文件。
