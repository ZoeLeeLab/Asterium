# 独立启动窗与主窗口交接

基线为 `ecda8b5e2bff1160db323b619dbe32cda4757b1f`，继续使用现有启动修复工作树。本次只修正启动呈现与窗口显示时机，不变更消息、权限、历史存储或已有性能修复。

## 目标和边界

- 启动时显示居中的小型无边框动画窗，复用已确认的圆润星形和文字间距，无产品名称或模拟窗口按钮。
- 主窗口始终隐藏，直到真实资料就绪、路由内容提交且至少完成一次绘制机会，再一次性交接。原生 `ready-to-show` 只能证明第一帧可以显示，不能独自证明 React 内容已就绪。
- 没有最短动画时长或动画结束等待。加载快时直接进入主界面；加载慢时小启动窗继续轻量等待。
- 读取、页面加载或渲染失败留在启动窗，可重试或退出；关闭启动窗退出整个尚未就绪的应用。第二次启动／托盘唤回不得提前显示隐藏的主窗口。

## 数据流和职责

1. Main 的 StartupWindowService 负责两个窗口的交接、启动状态、发送方检查和清理，原窗口构造和系统设置仍归 main.ts。主窗口的原生可显示状态与页面实际绘制报告都就绪后才显示。
2. Preload 分开：原主窗口桥增加固定启动报告和重试通知；独立启动窗使用专用 Preload，只暴露查询状态、重试、退出和状态订阅，不注入完整业务桥。
3. Shared 提供启动状态／桥类型；启动 IPC 只有固定操作枚举，校验当前主窗口或启动窗的顶层 frame，不接受任意路径、脚本或凭据。窗口生命周期 IPC 由服务独立注册及清理，不进入 agentIpc.ts 的业务注册／清理表，避免交接窗口生命周期与代理生命周期互相干扰。
4. Renderer 启动入口不加载 PrototypeProvider 或聊天资料，只渲染已确认的 StartupStatus。主入口仍读取资料，在 App 路由内容提交后的绘制机会报告就绪；本机主窗口不再插入全屏动画。
5. 开场与等待动作继续由既有 CSS 执行。新增入口 HTML／TSX 和专用 Preload 是独立原生窗口的必要边界，不再拆分角色绘制函数或新增纯转发模块。

## 验证

先补回归：原生 ready-to-show 不能提前显示主窗；真实页面报告后交接且不等动画；错误／重试、重复报告、过期窗口／子 frame 拒绝、唤回与统一清理。真实 Electron 使用隔离合成资料，确认启动时只见小窗、主窗首次显示已有内容、失败可恢复、快慢加载均不闪空背景，重启和退出无残留。随后默认全量、类型、Lint、能力及隐私检查；不改其他工作树，也不覆盖旧验收包或原始证据。

参考 Electron 官方 BrowserWindow 文档的 ready-to-show／paintWhenInitiallyHidden 说明，以及 Security 文档的 Validate sender 条目；仅核对窗口绘制与发送方语义，不修改项目的公开链接白名单。

## 结果与交付

- 修复前的 Renderer 回归确认：本机主窗口会在加载期间插入全屏动画，无法满足独立启动窗要求。修复后主窗口仅在资料就绪及真实路由经过绘制机会后报告；无动画结束事件或秒数门槛。
- 原生窗口定向 24 项通过；更新域独立测试将新的窗口服务作为边界 mock，保持其原有更新合同断言，窗口服务本身由专门测试与真实 Electron 验证。
- 真实隔离 Electron 使用生产 Main、两个 Preload、两个 Renderer 入口并装入测试 ASAR。快加载、受控慢加载、读取失败重试、退出四种情形通过；主窗口首次显示均已有导航内容且没有全屏动画，慢加载时只见 520×450 启动窗；重复唤回不提前显示主窗；关闭后无遗留测试进程。启动窗不含聊天、工作区或凭据桥，轮廓实际支持圆弧，提示与信封留有间距。
- 原测试入口有一处生成 JavaScript 的引号转义错误，首次触发了原生错误框。保留失败记录并修正；现于启动进程前用 Script 编译检查生成入口，测试进程异常转入诊断并退出，避免再次弹出测试错误框。初次文件模式测试遗漏相对静态资源基址也已修正；这些是隔离测试工具的问题，未读取日常资料或改变产品加载条件。
- 引入第二个原生窗口后，离线 Electron 验收明确选择主文档，而非随意选择第一个文件窗口，保持历史、存储、扩展与 API 断言原样。
- 全量回归暴露既有 API 凭据测试的时序竞态：提示文本提交并不等于 Provider 的保存 effect 已执行。断言现在等待新伙伴的凭据引用落盘，再同时检查没有明文密钥，避免检查旧快照时误通过隐私断言；未改凭据或存储业务、未放宽测试超时。
- 最终默认全量 297 个文件、2149 项通过，原有 2 项 TODO；类型、Lint、隐私、能力词典、Renderer 构建和历史强退恢复检查通过。Lint 仅原有 15 条 Hook 警告。窗口失败后的迟到就绪报告保持拒绝，未就绪的主窗不会被放行。

新增产品文件仅为窗口生命周期服务、共享合同、独立窗 Preload、独立 HTML 与 Renderer 入口。三个入口文件是隔离原生窗口及构建的必要文件；共享角色绘制仍在原组件内，主窗就绪报告仍在 App 内，没有一函数一文件或转发空壳。

仍使用原独立分支修复并制作私用验收包，不推送、不合并 main，不改变其他工作树。正式候选和本轮工具证据单独版本化，保留先前验收包。
