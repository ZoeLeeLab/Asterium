## 原始诊断归属

## 维护者确认后的验收口径

- Full 对普通原生命令按当前账户权限放行；选择该模式就是对此模式的授权，不提权。允许后访问账户可访问的路径是预期行为。
- 手动模式必须等待对应运行和会话的用户允许；拒绝不能执行。取消、超时、断连和重复／过期答复继续按原检查拒绝。
- 只读模式继续拒绝原生命令；显式文件操作和受管资料服务保留自己的校验。
- 主审批、路径字符串检查与 Hooks 不构成任意原生代码的操作系统级文件隔离。不会通过新增黑名单、Claude 专用沙箱或静默删掉命令能力来改变范围。

测试按这个明确的产品约定增加 Full、只读及手动允许／拒绝用例，取代先前错误的 Full 必须 deny 期望，保留原始证据。真实订阅与普通账户安装仍需各自验收。

## Wake 独立定位

Wake mock 的扫描游标在 observe() 时已持久化，但后续 SSE checkpoint 尚未处理完，session 的 caughtUp 仍为 false；此时 tick 正确地不投递。原验收在游标出现后只 tick 一次，过早断言了入队数。

验收改为在既有期限内等待实际入队，仍严格断言一次投递、无重复连接、未知回执不自动重试和其他群继续工作。另加受控延迟 checkpoint 测试，证明游标已持久化时不得过早投递，checkpoint 完成后恰好投递一次。没有改变 Wake 业务代码或宣称 CyberBoss 原线程已真实接通。
