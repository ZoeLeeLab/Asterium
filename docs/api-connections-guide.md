# API 伙伴配置与验收

## 配置入口

设置 → **伙伴管理 → 新增伙伴 → 添加新伙伴**。连接配置直接放在 API 伙伴表单中：

1. 从“API 站点”选择 **DeepSeek、Kimi、OpenAI、Anthropic、硅基流动**。
2. 填写 API Key，点击“拉取模型”，在模型框选择站点返回的模型。已经保存过的站点不必重复填 Key；读取失败也可手动填写模型 ID。
3. 填写伙伴名字及称呼，保存伙伴。日常连接只需站点、Key 和模型；高级模型设置默认收起。

默认站点的协议／地址已配置：DeepSeek、Kimi、硅基流动用 Chat Completions，OpenAI 用 Responses，Anthropic 用 Messages。模型列表按站点原样提供，不按模型名称猜测能力；非聊天模型是否可用于对话以服务说明为准。Anthropic 新模型预置最大输出 4096 token，可在高级区调整。保存不调用模型，拉取列表只调用模型目录接口。

需要中转站或其他地址时，在下拉菜单底部点 **＋ 自定义配置…**。弹窗填写名称、地址、Key，选择四种通用协议之一；Headers 可选，通常无需填写。点击“确认”后站点立即保存并出现在下拉菜单中。选中自定义站点后，其右侧“编辑”按钮可打开同一弹窗修改或删除。取消弹窗不会保存。

已有连接均保留在下拉菜单中，不按 URL 擅自合并。站点连接可供多位伙伴复用，人设、记忆、会话和目录授权独立。更换共享站点 Key 时界面提示受影响范围；站点弹窗显示引用伙伴数量，仍被使用时禁止删除。未使用站点删除时，同时删除其无引用模型配置。模型参数的修改保存为该伙伴的新配置，避免影响其他伙伴。删除伙伴不删除共享密钥。

默认站点只需要填写 Key；若需另一地区或自定义路由，请新增自定义站点。预设地址依据官方文档核对：[DeepSeek](https://api-docs.deepseek.com/)、[Kimi](https://platform.kimi.com/docs/get-api-key)、[OpenAI](https://developers.openai.com/api/reference/resources/models/methods/list)、[Anthropic](https://platform.claude.com/docs/en/api/overview)、[硅基流动](https://docs.siliconflow.cn/docs/userguide/quickstart)。

| 协议 | 地址示例（示例域名不会自动访问） | 默认认证 | 特别说明 |
| --- | --- | --- | --- |
| OpenAI Chat Completions | `https://api.example.com/v1` 或完整 `/v1/chat/completions` | Bearer | 默认协议，兼容常见中转站 |
| OpenAI Responses | `https://api.example.com/v1` 或完整 `/v1/responses` | Bearer | 本地管理历史，`store:false` |
| Anthropic Messages | `https://api.example.com/v1` 或完整 `/v1/messages` | x-api-key | 新模型预置最大输出 4096 token，可调整 |
| Gemini Generate Content | `https://api.example.com/v1beta` 或完整模型端点 | x-goog-api-key | model ID 可带 `models/`；完整端点的模型必须匹配 |

根地址自动补协议默认版本，已经提供版本路径时不重复追加。非标准路由在高级设置覆盖，并核对协议与站点文档；Gemini 路径可用 `{model}`、`{method}` 占位符，运行时填入准确模型和生成方法。Key 单独填写，不放进 URL、模型名或扩展 JSON。

## 高级配置

高级区默认收起。参数留空时不强制发送；协议必填项例外，Messages 的输出上限默认 4096 token。

- 可选鉴权方式、附加请求头、请求／模型列表路径、流式开关、超时。附加头 JSON 只用于输入新值，保存后单独加密，不回显；留空保留，`{}` 清除。不能覆盖受管理的 HTTP／认证头，认证方式在专用选项中设置。
- 温度、Top P、输出上限和思考 JSON。Chat Completions 输出上限默认使用 `max_completion_tokens`，需要旧格式的兼容站可选择 `max_tokens`；旧 DeepSeek 默认沿用 `max_tokens`。思考 JSON 使用目标协议原生结构，不按模型名称猜测功能。
- 扩展 JSON 不得覆盖消息、模型、工具、认证、普通生成参数等托管字段。Gemini 扩展和思考参数进入 `generationConfig`；其他协议使用相应请求字段。冲突配置拒绝保存。
- 新模型默认开启文字和工具调用，可在高级模型设置手动关闭工具；已有模型保存的开关值保留。聊天图片仍需明确启用；开关不会扩大工作区、成员关系或审批权限。图片另受格式、大小和适配器上限约束。

如果伙伴说没有自动化入口，或把 `<asterium_status .../>` 一类标签直接写在回复里，先检查 **API 伙伴编辑 → 高级模型设置 → 启用工具调用**。关闭时所有工具都不会发送给模型，标签只是普通文字，不代表查询或执行。勾选并保存后下一轮生效，可以继续原对话，不必重开线程；开启后原生工具列表提供 `asterium_automation`，创建任务仍需星丛确认。表单模型下会直接显示工具状态，当前请求也会明确告知伙伴，以免旧启动资料误导。

- 响应头默认等待 120 秒，建立流后没有读空闲超时，整轮超时默认关闭。可用聊天停止或高级区的“取消测试”中止。网络失败不会自动重发模型请求、切换站点或协议。
- 上下文窗口未知留空，不猜测；原有历史上限和手动 `/compact` 可继续使用。自动压缩默认关闭，启用须填写输入预算。预检用保守字节估算而非精确 tokenizer，可能提前要求压缩；保留最近六轮，失败或仍超预算则停止，不继续发送过大请求。

## 换模型与续聊

修改服务、协议或模型后下一轮使用新快照，正在运行的任务继续使用启动配置。默认保留公开对话、摘要、已完成工具结果，旧工具不会重新执行。同绑定保存并回传需要的原生输出、签名和思考状态；跨绑定清除不能迁移的状态。Gemini 的跨协议工具事实转换为标注的历史文本，不伪造签名。

需要重新开始时，在单聊中新建会话。若目标模型不能接收原图片，附件引用保留并标明当前无法查看，不声称新模型看过图片。

## 自动验收与人工验收

`npm run test:api-providers` 启动已打包的应用，使用临时用户数据、系统加密的合成凭据、loopback HTTP 模拟服务，核对四协议读写、工具往返、切换、取消及重启。不会读取私人凭据或请求真实模型。测试证据位于忽略目录 `.qa/api-providers/`。另有全协议 16 组切换、自动压缩及权限回归单元测试。

真实验收由用户指定服务、协议与模型后执行。本轮用户选择稍后在界面自行配置，真实连接状态仍为**待人工验收**：

1. 运行 `out/Asterium-win32-x64/Asterium.exe`，进入设置 → 伙伴管理 → 添加新伙伴，选择预设或添加自定义站点，填写 Key、拉取并选择模型，保存伙伴。不要在聊天里发送 Key。
2. 重新进入该伙伴编辑，在“高级模型设置”中点击“发送测试对话”，确认返回文字。按需测试流式／非流式；可用“取消测试”中断。
3. 若模型支持工具，点击“测试工具调用”，确认返回预期测试调用。这个按钮只检测合成工具，不读写文件。随后启用该模型的工具能力。
4. 让 API 伙伴在已授权临时目录读取一个测试文件；确认内容正确。写入仍应按现有权限提示。支持图片时明确启用图片输入，再发送一张测试图检查。
5. 在同一会话确认一个无隐私的测试标记，再切换模型／协议并询问该标记；确认续聊。切换不支持图片的模型时，应看到能力限制说明。
6. 关闭并重新启动星丛，检查共享绑定、旧伙伴、会话和凭据状态仍在。若服务报错，记录协议、model ID 与脱敏错误码即可，不提供 Key。

模拟通过不代表所有站点或所有模型都通过；四个协议分别记录真实验收结果。语音、视频、图像生成及 Gemini Interactions 不在本轮范围。
