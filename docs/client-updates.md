# 客户端更新

关于页集中显示当前版本、更新状态、更新历史和更新偏好。流程是：检查新版本 → 使用者选择下载 → 下载完成并校验 → 使用者再次确认退出并启动安装向导。检查不会下载，下载不会自动安装；退出安装会结束正在运行的任务，先保存编辑内容。

“启动时自动检查更新”和“接收测试版更新”保存在本机通用设置中。可关闭启动检查并改用手动检查。关闭测试版通道后只考虑正式版本；版本按数值语义比较，不按字符串排序，不安装同版或旧版。

## 当前候选的配置状态

首版已实现 GitHub Releases 检查、下载、进度、取消、校验和用户确认安装流程。2026-11-01 维护者手动创建公开空仓库 [ZoeLeeLab/Asterium](https://github.com/ZoeLeeLab/Asterium)，当前源码已绑定该更新地址。只读核验时仓库为 public、大小为 0，分支及 Release 列表均为空；未上传源码或安装包。地址绑定不代表已有可下载版本或真实升级验收通过。

当前还没有 Release，公开列表为空，客户端不会提供下载或执行安装。新绑定仅在源码启动或重新构建后生效；旧候选安装包仍保持“更新源待配置”，检查与相关设置不可操作，不发起更新请求。新包不沿用旧包的验收归属。

源码中唯一配置入口为 `src/shared/appUpdates.ts` 的 `PUBLIC_UPDATE_REPOSITORY`，填写公开仓库的 `owner/repository` 后重新构建候选。该字段只能由维护者随源码发行，不接受模型、聊天消息或渲染页传入下载地址，不放入私人 GitHub Token。绑定地址不等于创建远端或公开发布，仍需维护者另行指令。

## 后续公开发行的约定

1. 每个版本创建明确的 GitHub Release，标签为 `v<package.json 版本>` 或版本本身，结束 draft 状态。
2. 上传经独立验收的 Windows x64 安装器。文件名保持构建配方：`Asterium-<版本>-win-x64-<12 位源码提交>-setup.exe`；同一个 Release 只保留一份匹配的安装器，不能混入同版的多个候选。
3. 核对公开 Release 资产的 `state=uploaded`、字节数与 `digest=sha256:<64 位哈希>`。更新器使用 GitHub 公共 REST API 返回的摘要；摘要缺失、存在多个匹配包、大小异常或来源不符时拒绝下载，不降级为无校验安装。
4. 将 Release Notes 写入 Release 正文。API 按最近 20 个发布记录检查，包含测试版；客户端选取其中符合通道且版本更高的一项。维护者须先检查该范围能覆盖计划发布的通道，不使用普通 Git 标签代替 Release。
5. 更新地址只能使用配置仓库对应的 GitHub 下载入口；只跟随受限的 GitHub 官方 HTTPS 资产域名重定向。安装包下载到当前星丛数据目录的 `updates` 子目录，不写入程序安装目录，不要求管理员权限，不携带登录凭据或本地资料。

下载按声明大小限制并校验 SHA-256，取消或失败清理本次临时文件；安装前再次校验。用户确认后启动同一套当前用户安装向导并彻底退出星丛。保留 Beta 安装身份、快捷方式偏好及默认数据目录；不删除、迁移或覆盖用户资料，不静默安装。自定义数据目录仍需使用原有启动参数，安装向导不会自动把测试目录切换成默认目录。

SHA-256 与 HTTPS 来源校验不等于代码签名，当前候选仍未签名。项目许可证与第三方剩余问题也不会因更新功能完成而自动解决。

## 验收范围

自动化测试使用模拟 GitHub 响应和合成文件，覆盖通道与版本选择、错误源/重定向、缺失摘要、取消、大小与摘要不符、安装前缓存篡改、分开的下载和安装确认；不会实际执行安装器。绑定公开仓库后，还必须验证真实公开 API、下载、当前用户升级、设置及数据保留和重装行为，再据实记录结果。

接口依据：[GitHub Release 列表](https://docs.github.com/en/rest/releases/releases#list-releases)、[Release 资产与 digest](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)。
