# 客户端更新

关于页集中显示当前版本、更新状态、更新历史和更新偏好。流程是：检查新版本 → 使用者选择下载 → 下载完成并校验 → 使用者再次确认退出并启动安装向导。检查不会下载，下载不会自动安装；退出安装会结束正在运行的任务，先保存编辑内容。

“启动时自动检查更新”和“接收测试版更新”默认开启，保存在本机通用设置中。可关闭启动检查并改用手动检查；已运行的客户端不会持续轮询，发布新版后可重新启动或到关于页检查。关闭测试版通道后只考虑正式版本；版本按数值语义比较，不按字符串排序，不安装同版或旧版。

## 当前公开发行状态

首版已实现 GitHub Releases 检查、下载、进度、取消、校验和用户确认安装流程。2026-11-01，[ZoeLeeLab/Asterium](https://github.com/ZoeLeeLab/Asterium) 已公开源码及 [v0.1.0-beta.1 未签名预发行版](https://github.com/ZoeLeeLab/Asterium/releases/tag/v0.1.0-beta.1)，发行页提供 Windows x64 安装器、配套源码与 SHA256SUMS.txt。

已发布客户端绑定上述公开更新源。已安装 Beta.3 的用户可在「关于」里检查 [Beta.4](https://github.com/ZoeLeeLab/Asterium/releases/tag/v0.1.0-beta.4)。请开启「接收测试版更新」以发现预发行版本。同版本的本地候选可通过手动安装更新。

源码中的配置入口为 `src/shared/appUpdates.ts` 的 `PUBLIC_UPDATE_REPOSITORY`，现值为 `ZoeLeeLab/Asterium`。使用者检查或下载公开版本不需要 GitHub Token。变更更新源须由维护者修改源码并重新构建，不接受模型、聊天消息或渲染页传入下载地址；后续公开发行仍须维护者明确授权。

## 后续公开发行的约定

公开前须对冻结源码、拟上传材料和新增 Git 历史完成 [隐私检查](privacy-checks.md)，并完成对应候选的安装验收。

1. 每个版本创建明确的 GitHub Release，标签为 `v<package.json 版本>` 或版本本身，结束 draft 状态。
2. 上传经独立验收的 Windows x64 安装器。文件名保持构建配方：`Asterium-<版本>-win-x64-<12 位源码提交>-setup.exe`；同一个 Release 只保留一份匹配的安装器，不能混入同版的多个候选。
3. 核对公开 Release 资产的 `state=uploaded`、字节数与 `digest=sha256:<64 位哈希>`。更新器使用 GitHub 公共 REST API 返回的摘要；摘要缺失、存在多个匹配包、大小异常或来源不符时拒绝下载，不降级为无校验安装。
4. 将 Release Notes 写入 Release 正文。API 按最近 20 个发布记录检查，包含测试版；客户端选取其中符合通道且版本更高的一项。维护者须先检查该范围能覆盖计划发布的通道，不使用普通 Git 标签代替 Release。
5. 更新地址只能使用配置仓库对应的 GitHub 下载入口；只跟随受限的 GitHub 官方 HTTPS 资产域名重定向。安装包下载到当前星丛数据目录的 `updates` 子目录，不写入程序安装目录，不要求管理员权限，不携带登录凭据或本地资料。

下载按声明大小限制并校验 SHA-256，取消或失败清理本次临时文件；安装前再次校验。用户确认后启动同一套当前用户安装向导并彻底退出星丛。保留 Beta 安装身份、快捷方式偏好及默认数据目录；不删除、迁移或覆盖用户资料，不静默安装。自定义数据目录仍需使用原有启动参数，安装向导不会自动把测试目录切换成默认目录。

SHA-256 与 HTTPS 来源校验不等于代码签名，当前候选仍未签名。项目许可证与第三方剩余问题也不会因更新功能完成而自动解决。

## 验收范围

自动化测试使用模拟 GitHub 响应和合成文件，覆盖通道与版本选择、错误源/重定向、缺失摘要、取消、大小与摘要不符、安装前缓存篡改、分开的下载和安装确认；不会实际执行安装器。

首次公开发行已核对真实 GitHub 发行数据、三项资产的大小与 SHA-256，以及未登录页面和下载入口。首次从 0.1.0-beta.1 到更高版本的客户端实际下载、确认安装、设置及资料保留和重装行为仍待单独验收；公开入口与摘要核对不代替完整升级测试。安装器构建来源及原候选验收归属保持不变，见 [r4 记录](releases/0.1.0-beta.1-r4.md)。

接口依据：[GitHub Release 列表](https://docs.github.com/en/rest/releases/releases#list-releases)、[Release 资产与 digest](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)。
