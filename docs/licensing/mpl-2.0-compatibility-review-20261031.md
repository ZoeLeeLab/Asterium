## 一、先明确方案边界

- MPL-2.0 是文件级 copyleft：对受其约束文件的修改，在发生相应分发时需要按其条件提供源码；它允许与其他许可的独立文件组合，第三方文件仍保留自己的许可。压缩后的客户端 JS 也属于需要关注分发义务的交付内容。[Mozilla FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)
- MPL 允许商业使用，不保证只有原作者可以收费。付费云服务、官方签名构建和企业支持可以分别设计；仅在服务器运行而不交付副本的代码，与下发给用户的客户端代码有不同的分发边界。各服务供应商自己的条款仍单独适用。[MPL 正文](https://www.mozilla.org/en-US/MPL/2.0/)
- 建议将“保留官方发行权”写成“保留品牌、官方发行身份、官方签名密钥与官方发布渠道的控制”。MPL 不授予商标使用权，但允许合规的修改和再分发；不能通过附加品牌政策收回代码许可已授予的权利，也不能把只有官方可以发行或商用写入标准 MPL。
- 品牌政策可要求不得冒充官方或暗示未经授权的背书；是否允许标识使用、怎样说明衍生版本应另写清楚。当前没有审查商标注册情况，不使用已注册标记或声称已经获得注册保护。
- “客户端自研代码开源”不等于“安装包内所有第三方代码统一改用 MPL”，也不等于整个安装包都是自由开源组件。尤其要单列下面的 Claude Agent SDK。

## 五、Claude Agent SDK 的单独待确认项

本地 SDK 的 `LICENSE.md` 声明保留权利并指向供应商法律协议；该文件已在候选中保留。MPL 只能用于有权授权的自研文件，不能将 SDK 重新许可。

[供应商法律与合规说明](https://code.claude.com/docs/en/legal-and-compliance) 区分 API / 商业协议、原生 CLI 使用以及第三方产品中的认证方式。现有架构使用 SDK 并指向用户另行安装的 CLI，应继续核对：

1. SDK 客户端文件随安装包再分发的允许范围，以及需保留的通知。
2. 星丛的具体调用和认证链路属于哪种场景；用户自行登录原生 CLI 与第三方代收、代存或转发订阅凭据不能混为一谈。
3. 本地 BYOK / 原生登录、未来云服务与代付转售分别适用的限制，不能从客户端可用推断云端经营方式也可用。

在上述项确认前，不能将当前安装包宣传为所有第三方组成部分都是 MPL 或全部自由开源。可以保留“自研客户端源码拟采用 MPL”的方向；若目标是整个交付物均为自由开源组件，则需要另行评估可选依赖或替代接入方案，本轮未重构产品。

## 六、已有第三方声明与交付缺口

- 当前 `THIRD_PARTY_NOTICES.md` 重点覆盖 Wake SDK 的 zod、MCP、MouseCrew、YAML，不能据此认为桌面应用全依赖已覆盖。
- 候选保留 Electron 的 `LICENSE` 与 `LICENSES.chromium.html`。Chromium 声明中存在若干同名许可或组件，不足以证明它替星丛额外打包的全部 JS 依赖完成了署名。
- 对照独立文件哈希，多个直接依赖的完整许可未以独立文件原样出现在候选中。这是待补声明映射的证据，不单凭文件名缺失就断言所有声明均缺失；仍应检查聚合声明、源码注释及生成流程。
- `MouseCrew` 固定版本的实际 MIT 文本署名为 `mousecrew contributors`，当前自有声明使用了另一种署名表述；应按上游文本核对并修正自有说明，原许可证保持不动。
- 安装器实际含 `nsDialogs.dll`、`nsExec.dll`、`nsis7z.dll`、`StdUtils.dll`、`System.dll`、`UAC.dll`、`WinShell.dll`。这些与仅用于构建的压缩工具不同，插件各自的许可与分发条件仍需列明，不能一律套用 electron-builder 的 MIT。

后续应生成可随包交付的完整第三方通知与许可集合，并在构建检查中核对。新的说明补齐不回写旧安装器，也不改变其哈希或原审计证据。

## 八、正式落许可证前的关闭清单

1. 确认自研源码与第三方文件边界，保留第三方原许可证和通知，不批量覆盖 vendored 或 SDK 文件。
2. 确认 SDK 再分发与认证场景，记录上游条款和必要的授权确认；未确认项不标通过。
3. 为 ELK / MTX 等实际交付代码补正确版本、许可与源码获取说明，明确双许可分支。
4. 追溯 bundle 模块、内嵌代码 / 数据 / 字体 / WASM，补全桌面应用和安装器插件的声明交付。
5. 补资产来源与品牌使用范围；拟定不限制 MPL 权利的商标 / 官方渠道政策。
6. 上述范围确认后，再添加未改写的 MPL-2.0 正文和适用的源码头 / SPDX 标识，明确源码获取方式；文档、品牌资产与第三方例外单独列明。
7. 在新候选中验证许可集合实际随包交付，分别记录许可证审查与功能验收，不从功能测试通过推断许可审查完成。

当前不把清单作为“全部已完成”。本轮清单和初审可以供正式许可决策使用，待确认项保留。
