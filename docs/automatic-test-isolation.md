# 自动测试目录与生命周期

## 统一入口

`npm test` 和直接运行 Vitest 都通过项目配置建立新的 `%TEMP%/Asterium-AutoTest/run-<随机值>`。每个测试文件分配新的 `worker-…`，每个用例再分配 `case-…`；单 worker 内的显式并发用例串行执行，多个 worker 仍可并行，不共享 TEMP/TMP。浏览器存储继续由测试设置逐例清理。

35 个独立 `tests/*.mjs` 检查入口使用 `runAutoTest`。直接执行单脚本也建立新运行目录；编排器启动的子脚本继承运行归属、另建 worker。临时文件、项目、截图、日志和 Vite 缓存都在所属运行中，固定 `.qa` 证据路径和固定本地视觉服务端口不再复用。

Wake／自动化适配器检查在当前 worker 内从源码构建测试 SDK，不读取或覆盖共享 `out` 中的旧构建物。该动作只生成临时测试库，不生成产品应用包或安装器。

被测星丛必须显式指定 user-data-dir，托管启动器会写入当前测试目录的 autotest 归属并传入 `--asterium-profile=autotest`。候选兼容性检查拒绝未包含启动隔离的旧产品包；不会退回日常或开发资料。检查所需的系统临时目录只作为本测试进程树的环境值传递，不修改 Windows 全局变量。

本轮不构建或运行新产品候选；旧 Beta 不作为新的打包检查目标。真正的包内界面检查须等待另行授权且包含新源码的固定候选，不把脚本迁移等同于这些检查已经通过。

## 结果保留与清理

独立入口依次完成执行、关闭注册的服务／浏览器／子进程、记录 worker 完成状态，然后才核验归属、真实路径和目录链接并清理本次运行。执行和清理同时失败会保留两个错误及原始目录，不吞掉原异常。Vitest 记录本轮模块结果，成功的普通单次运行默认清理，失败保留并打印目录。

需要保留成功运行的截图或日志时，在当前终端仅为本次调用设置 `ASTERIUM_AUTOTEST_KEEP=1`。watch 模式在同一调用内持续分配新的 worker／case，保留运行目录，退出后再显式清理。不得把数据指向开发目录、人工验收批次或旧证据目录；旧的外部 `--output`／证据路径覆盖不会被静默沿用。

明确清理单个已停止的运行，先只读查看，再按需执行：

```powershell
npm run test:cleanup -- --run '<本次运行的完整路径>'
npm run test:cleanup -- --run '<本次运行的完整路径>' --remove
```

清理器只接受带正确归属的单个 run 目录；不枚举清理 `%TEMP%`，不处理旧格式证据。仍在运行的所有者／worker、未确认退出的任务、目录链接或归属不符都会拒绝。进程异常退出不会触发下一次运行的批量清理。

## 真实连接边界

默认离线或模拟检查不读取实际日常／开发凭据。真实 API 脚本仍要求显式 opt-in 和用户指定的 test-only 来源；来源必须有 acceptance/autotest 归属标记，日常／开发目录及目录链接均拒绝。本轮不运行真实 API、官方 CLI 会员服务或外部宿主联调。

新增生命周期探针只启动合成 Node 进程，用于核验全新目录、并发、成功清理、失败留存、错误归属、junction、子进程退出和双错误保留；预期的探针失败不是把真实测试失败改写为通过。
