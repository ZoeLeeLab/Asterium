# Claude 本地 CLI 接入与验证边界

本地伙伴使用用户自行安装、登录的官方 Claude Code。星丛不实现新的登录或订阅令牌服务，也不要求本地伙伴改用 API；API 伙伴仍是独立入口。星丛只管理自己启动的子进程，不自动更新用户的 CLI。

星丛仅在自己启动的 CLI 子进程环境中设置 `DISABLE_AUTOUPDATER=1`，避免会话启动触发后台自更新，不修改用户全局设置或官方二进制。变量含义见[官方更新说明](https://code.claude.com/docs/en/setup#disable-auto-updates)；用户仍自行管理 CLI 版本。

维护者已明确：Claude 原生命令沿用现有审批桥接；Full 模式表示授权使用当前 Windows 用户权限，允许后读取该账户可访问的路径属于预期行为。本轮不为 Claude 新建权限架构或沙箱。前次编码路径诊断及语义澄清保留在[原始诊断记录](claude-cli-release-blocker.md)，不将该观察改写成历史测试已通过。

## 当前实现

- 官方 CLI 处理原生会话、模型请求与认证；星丛通过 stdin、流式 JSON、会话 ID 和本机 MCP stdio 连接它。
- CLI 启动参数中的显式 ask 规则将原生操作交给星丛审批；记忆、笔记和协作继续使用星丛现有业务服务。
- MCP stdio 子进程通过 Windows 命名管道回到当前运行的主进程。管道仅授权当前账户和 SYSTEM，并拒绝网络登录；客户端还必须属于该次 CLI 的进程树。不同运行不共用管道，不监听 HTTP 端口。
- 手动模式的普通原生命令需经用户允许；拒绝、取消、过期或失联不得产生允许结果。Full 模式对普通原生操作按当前账户权限放行；选择 Full 本身就是对此模式的授权，不会提权。只读模式拒绝命令操作。卡片归属与一次性消费继续由现有桥接检查。
- 显式文件路径和受管资料服务仍执行既有校验，但字符串检查不是任意原生命令的操作系统级文件隔离。Hooks 只作额外防线，不使用 CLI 的 bypass 参数替代主审批，也不声称 Hook 能封闭 Full 原生进程的文件访问。
- 资料快照继续由星丛保存；重读、失败恢复、压缩和日记仍使用原服务。没有自动导入外部聊天或已有记忆。

## Windows 验证

诊断脚本在开发机运行真实官方 CLI，但把模型响应限制到本地合成服务，不使用会员账户、私人项目或真实模型。HTTP 仅属于这个测试服务，不是产品 MCP 网络桥接，也不是产品的 API 替代接入。

```powershell
node scripts/build-claude-bridge.mjs
node tests/claude-cli-acceptance.mjs --cli '<官方 claude.exe 的绝对路径>' --output '<本轮证据目录的绝对路径>'
```

参数占位需要替换后才能运行；不把此命令交给没有开发环境的测试电脑。每次运行创建新证据子目录，保留失败尝试，输出 CLI 哈希、Windows 版本、源码提交及工作区状态，不把未提交的验证当作候选构建验收。

2.1.295 不是安全保证，2.1.316 也不是自动放行条件。开发阶段在官方 2.1.316 中复现了“缺失 PowerShell Hook 脚本没有阻断”的路径；主 MCP 审批仍拒绝了写入。上游记录见 [#100891](https://github.com/anthropics/claude-code/issues/100891)。

支持版本只依据具体 Windows 实测结果列入对应候选报告；不推断所有更高版本均通过。真实会员订阅、完整产品界面与普通账户安装仍需独立人工验收。

## 协议与数据兼容

前端 PartnerAdapter 事件、伙伴 ID、原生会话绑定和业务数据格式保持不变。当前源码已移除 npm Agent SDK 依赖；旧候选及其 SDK 许可记录仍作为历史保留。Codex 的接入、认证与协议实现未因本次替换而更改。
