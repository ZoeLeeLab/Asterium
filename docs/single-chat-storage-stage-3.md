# 单聊存储迁移第三阶段

第二阶段代码提交为 `3861b7a`，能力核验提交为 `f50a6f9`。本阶段接入可重建索引、按页读取和搜索。

## 存储与数据流

- `events.jsonl` 继续作为星丛单聊历史的数据源。当前资料目录里的 `single-chat-history.v2/history-index.v1.sqlite` 是可重建的读取投影。
- `SingleChatHistoryIndex.ts` 的 `chats` 表保留会话元数据、挂起状态、日志版本、完整记录的最后字节位置以及文件大小和修改时间。 `messages` 表保留会话内位置、消息 ID、渲染数据和搜索文本。支持 FTS5 trigram 时通过 `message_terms` 查找三字以上的词。更短的词和不支持 FTS5 的运行时使用字面包含查询。
- `SingleChatHistoryStore.ts` 第一次建立索引时逐行读取日志。索引有效时，启动发送所有会话的元数据和当前会话的最新页，其他会话首次打开时再加载。分页每次最多 80 条，约 4 MiB 的载荷目标保留目标消息或边界消息。单条消息本身可以超过该目标。
- 已有日志写入先追加并刷盘，再更新索引。有效索引可提供首次追加所需的尾部位置，索引暂不可用时可从 JSONL 确认写入位置。索引缺失、损坏或落后时重放对应日志。检测到损坏数据库时保留独立原件，重建过程不修改 JSONL。
- 主进程查询投影从索引取所需字段，省去工具时间线和附件细节。记忆、日记、自动化、交接的原查询接口继续使用该投影。

## 界面

- `useSingleChatHistory.ts` 保留当前会话末尾给发送和运行状态。 `useSingleChatTimeline.ts` 单独维护正在浏览的历史页。搜索跳到旧页后，继续发送仍使用真正的会话末尾。
- `ChatPage.tsx` 向上滚动或点加载按钮可读取前一页，保持原可见消息的位置。历史页可以加载较新记录或直接回到最新消息。旧页窗口接近三页时会分段显示，避免连续向上翻页把所有正文同时放入界面。左侧刻度显示已加载的回合，保留无滚动条的滚动和点击跳转。可以定位到未加载的发送记录与记忆来源。
- `ConversationSearch.tsx` 保留已渲染正文高亮，并从索引读取历史匹配。结果按页取出，点击或键盘选择可定位到旧记录。侧栏查询也会包含未加载的星丛会话正文。
- 本地 Codex 继续使用原线程进行续聊和原生分页。SQLite 查询目前覆盖已保存在星丛日志中的显示记录。原线程里仅存在于 Codex 的更早内容，需要沿原线程继续翻页。完整原生历史的索引和本地正文副本收敛仍待接入。
