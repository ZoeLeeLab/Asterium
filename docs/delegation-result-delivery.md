## 当前行为

新委派由 Main 记录原单聊、发起伙伴、线程绑定代次及工作区签名。结果返回后，原单聊空闲时续用原线程，让伙伴主动向用户汇报；原单聊忙碌时保留待送结果，由租约释放通知和 30 秒补查继续调度。用户新消息优先，可以中止自动汇报。

`wait_delegate_tasks` 可在同一单聊、同一发起伙伴的后续轮次读取完整结果。两分钟仅限制前台等待，不限制已完成结果的读取。前台已读取结果且该轮正常结束时，不再后台重复汇报。旧任务卡结果仍可跨轮查询，升级不会批量重放旧汇总。

read/write 继续是接回伙伴任务 message 中的一句要求；接收端仍使用原 v1 协议、原线程、原权限和审批，不新增服务器权限字段。它与自动汇报的只读限制分别作用于子任务和原伙伴的汇报轮。普通本地/API 一次性委派仍只读。完整边界见[委派权限说明](delegation-access.md)。

自动汇报的输入是宿主资料，不是新的用户授权。该轮使用只读执行策略；旧线程即使展示旧工具清单，宿主处理器也不提供再次委派、记忆写入、笔记修改或自动化管理。API 汇报关闭执行工具，并尊重原对话历史开关。后续用户轮在写租约内恢复自己的工具和工作区配置，排队期间不会提前替换正在运行的汇报配置。

## 模块与数据流

1. `PartnerDelegation` 保存任务、同单聊跨轮消费记录和结果投递状态；附件、接回伙伴协议保持原实现。
2. `DelegationConversationRuntime` 只从 Main 的绑定和来源快照构造原线程续答命令，复查线程、代次、工作区及删除／归档／停用状态。
3. `DelegationResultDelivery` 调度待送结果，区分运行接受与完成，处理用户优先和重启恢复。它不再次派发子任务，也不自行持有第二份写租约。
4. `RunCoordinator` 让后台汇报尝试获取现有写租约；忙碌时退回待送，取得租约后再次验证。本地适配器的本轮工具重绑在租约内完成。
5. `SingleChatMessageStore`／`SingleChatHistoryStore` 按普通 assistant 运行 ID 保存伙伴回复；窗口未打开也落盘，迟到的界面快照不会覆盖完整汇报。
6. `ConversationLifecycleService` 和附件维护 IPC 通过异步取消回调协调删除。第八阶段拆出的原线程服务及 Wake IPC 保留，`agentIpc.ts` 仅接线。

持久状态分为 pending、starting、accepted、completed、interrupted、uncertain、blocked。子任务完成不等于原伙伴已收到，更不等于已经向用户汇报。

## 重启与历史可见性

未开始发送的结果重启后可补送。外部复核仅查询原 requestId，不重新派单。删除、归档、停用、换线程或工作区变化后，不把结果送入新的上下文。

原生输入与本地文件没有跨进程事务。提交途中退出而无法确定是否被接受时保留 uncertain；已接受但回复中断时保留 interrupted，不盲目重发。可查看原线程或跨轮读取结果继续处理；这里不承诺所有断电时点都能自动补答。

内部输入仍保存在 Codex 原线程供模型使用，但星丛界面通过 Main 记录的 clientMessageId／原生 runId 隐藏其用户气泡。普通分页、搜索和定位共用过滤；伙伴回复、工具记录和同轮后续用户输入保留。真实用户即使引用相同内部标题或正文也不会按关键词被隐藏。重试保留先前输入身份，重启继续使用记录。过滤范围限定原单聊、原伙伴和原线程，Renderer 不能指定任意隐藏身份。
